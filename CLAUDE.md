# wald-arena — how this repository works

This repository enters `wald` on public boards: a Bayesian decision-theoretic contestant whose knowledge is an LLM, scored where others are scored. Its decisions are made by `wald` (github.com/gfrmin/wald), consumed as a library at a signed release; the law it decides under is in github.com/gfrmin/wald-charter (`CHARTER.md`, `CHARTER-v0.1.md`, `SURFACE.md`, `SURFACE-v0.1.md`). A **showcase** is an entry on a public board (`showcases/`); an **explainer** is a worked example that teaches how wald decides and is not played live (`explainers/`). "Who Wants to Be a Millionaire" is an explainer (`briefs/001-millionaire.md`); AA-Omniscience is the first showcase (`briefs/002-omniscience.md`). Read the brief for the part you are working on fully before anything else.

## Rules

1. **wald decides; nothing else does.** Every act the wald contestant takes comes from `wald.run` on a pack. No code in this repository ranks options, compares probabilities, or picks a lifeline on its own, except inside a board's baselines, which are labelled as baselines and never called by the contestant.
2. **No probability outside a pack.** Reliabilities, priors, values of the ladder: cells in packs under a showcase's or explainer's `packs/`, each with a source (`data`, `elicited`, `fitted`) and, for `fitted`, its held-out score. Python holds counts (right/wrong) and dollars; it does not hold a `0.83`. Calibration writes packs; it does not keep floats for the contestant to read.
3. **Packs are generated, never edited.** Each showcase and explainer has its own generator; Millionaire's `explainers/millionaire/make_stage_packs.py` writes all 120 stage packs from the ladder, the fitted reliabilities and the scored tables. A change to a pack is a change to the generator.
4. **wald is pinned.** `pyproject.toml` pins `wald` to a signed release tag (`v0.2.0`), and `uv.lock` to the commit it names. The pin is verified against `arena/allowed_signers` (principal `author@wald`, the same key `wald` and `wald-charter` carry) by `sh arena/verify_pin.sh` at every release bump: `sh arena/verify_pin.sh <tag>` before bumping, then with no argument after. An unverifiable tag is not pinned.
5. **Every spend is logged.** Each instrument call records model, tokens, dollars, latency, question id, tier. The scoreboard prices the act at the declared price, whether or not a cache served it.
6. **The owner's numbers are the owner's.** Ladder, λ_usd, models, question set, counts: from the brief, never chosen here. A missing number is a question in `QUESTIONS.md`, not a default.
7. **Report what it says.** The scoreboard prints the result as measured. Nothing is tuned to make wald look better; a baseline that wins is reported as winning.
8. **Keys from the environment**, never in the tree. `LLM_API_KEY` names; the loader fails loud without them.
9. **Layout.** `arena/` what every board shares: `transports.py` (the model providers, and the `Call` every spend is logged as), `config.py` (reading an owner file), `calibration.py` (the Beta mean and the one held-out scorer every fit uses, so scores compare across boards), `spend.py` (the append-only spend log, its resume and its replay), `report.py` (the scoreboard's formatting). `explainers/millionaire/` the Millionaire explainer: `oracle/` the exact game DP (pure Python); `baselines/` the LLM-plays-directly and always-answer contestants; `calibration/` its instrument reads, runs and fits; `questions.py`, `owner.py` and `owner.toml` its question set and its numbers; `play.py` the game runner; `scoreboard.py`; later `packs/` and `contestant/` (the wald contestant and its Door). `showcases/omniscience/` the AA-Omniscience entry. Each board has its own owner file and never reads another's, so a ruling for one board cannot move another. Anything that knows what a tier, a letter answer or a confidence bucket is lives with its board, not in `arena/`. `SCOREBOARD.md` the result; `QUESTIONS.md` what stopped you.

## The boundary, now that wald 0.2.0 is pinned

`contestant/` and each board's `make_stage_packs.py` can now be written against the pinned `wald`; nothing is written there until a session's brief asks for it. The oracle is the contract Millionaire's contestant will be judged against (`proto.py` in this repository; its `stage_world` and `solve_game` give the shape).
